# Pic365 无限画布产品开发与验收规格

文档版本：V1.12
更新日期：2026-08-29
适用范围：Pic365 单图创作工作流
文档用途：产品设计、研发拆解、自动化测试、浏览器验收、发布门禁

## 1. 产品结论

无限画布不是一个通用绘图软件，也不是把现有“灵感生图”简单铺到更大的页面上。

它的使命是：

> 让用户围绕一张图片，在不丢失思路、素材、任务和历史版本的前提下，持续生成、局部修改、比较、选择并交付最终作品。

产品完成的最低标准不是“能拖动卡片”，而是同时满足以下四条底线：

1. 作品不丢：上传素材、提示词、节点位置、生成结果和当前采用版本都能恢复。
2. 积分不乱：一次任务只预留和结算一次积分，失败或取消按既定规则释放或退款。
3. 任务可恢复：刷新页面、关闭浏览器或服务重启后，排队和运行中的任务仍能继续追踪。
4. 创作有闭环：从导入原图到生成分支、局部修改、版本比较、采用和下载，不依赖跳出画布才能完成。

## 2. 产品定位与边界

### 2.1 目标用户

- 想快速生成和修改单张商品图、广告图、社交媒体图片的普通用户。
- 需要反复尝试提示词、风格和局部调整的创作者。
- 需要保留多个方向并向客户展示版本演进过程的设计人员。

### 2.2 核心使用场景

1. 从一句想法开始，连续生成多个视觉方向。
2. 从历史作品或本地图片开始，保留主体并修改背景、风格或局部内容。
3. 从满意版本继续分叉，比较不同提示词、模型、尺寸或质量产生的结果。
4. 对某个局部涂抹后重新生成，而不是重做整张图。
5. 在多个结果中选定最终版本，预览并下载原图。
6. 隔天或换设备重新打开项目，继续上一次创作。

### 2.3 明确不做

- 不做 Photoshop 级像素编辑器。
- 不做 Illustrator 级矢量设计工具。
- 不做 PPT、详情页或多页面排版工具。
- 不做视频时间线。
- 首个正式版本不做多人实时同时编辑。
- 不把电商套图、批量 SKU 和多平台槽位功能搬进无限画布。

### 2.4 与“灵感生图”的关系

- 灵感生图：快速、线性、低学习成本的一次性单图生成入口。
- 无限画布：非线性、可分支、可比较、可回溯的深度单图创作工作台。
- 两者共享模型配置、计费规则、素材库、生成任务、历史记录和用户权限。
- 两者可以互相发送图片，但无限画布的核心闭环不得依赖跳转到灵感生图。
- 两者统一区分“母版”和“其他参考图”：母版是被编辑对象，其他参考图只提供主体、风格、构图或色彩信息；模型请求始终先发送母版，再发送其他参考图。
- 灵感生图允许把右侧参考图拖到左侧母版栏进行交换；无限画布的母版由当前选中实体决定，托盘中禁止交换母版。

## 3. 产品成功标准

### 3.1 用户成功指标

- 用户能在 3 分钟内创建项目并完成第一次生成。
- 用户能在 30 秒内从任意结果创建一个新分支。
- 用户能清楚回答“哪张是最终稿、它从哪里来、花了多少积分”。
- 页面刷新后，项目、画布位置、节点、任务状态和当前采用版本全部恢复。
- 失败任务不会破坏已有结果，也不会造成重复扣费。

### 3.2 产品指标

- 首次生成成功率。
- 有效项目中发生二次分支的比例。
- 生成结果被采用的比例。
- 局部编辑使用率。
- 项目次日继续编辑率。
- 单次成功作品平均生成次数和平均积分消耗。
- 任务失败率、取消率、退款异常率和恢复失败率。

### 3.3 发布红线

出现以下任一问题，不得发布正式版：

- 刷新或重新登录后项目丢失。
- 同一生成任务重复扣费。
- 失败或取消任务未按规则释放积分。
- 运行中任务在页面关闭后无法恢复。
- 用户无法判断任务是否仍在运行。
- 删除节点造成云端原图被误删。
- 未经确认清空整个画布或覆盖当前采用版本。

## 4. 信息架构

### 4.1 页面结构

1. 顶部栏
   - 返回首页。
   - 返回灵感生图。
   - 项目名称与保存状态。
   - 撤销、重做。
   - 自动整理、适应视图、缩放比例。
   - 项目菜单：重命名、复制、归档、删除。
   - 导出与下载入口。
   - 顶部栏属于独立交互层；点击、输入、下拉和轻微鼠标移动不得触发画布平移、框选或清空节点选择。
   - 项目栏与视图工具在常用桌面宽度保持同一横向层级，优先压缩按钮、字段和间距，不因普通桌面宽度拆成两条高菜单。
   - 下拉框、选项、弹层和按钮统一跟随全站深色/白色主题，不允许出现系统默认样式或与当前主题冲突的孤立色块。

2. 左侧素材栏
   - 当前项目素材。
   - 历史生成。
   - 本地上传。
   - 收藏素材。
   - 搜索、筛选、分页或继续加载。

3. 中央画布
   - 想法节点、图片节点、任务节点、分组框和连接线。
   - 平移、缩放、框选、拖拽和快捷操作。

4. 右侧属性栏
   - 节点信息。
   - 提示词与参考图用途。
   - 模型、尺寸、质量、生成数量和价格。
   - 局部编辑工具。
   - 版本操作与下载。

5. 底部任务区
   - 排队、运行、取消中、完成、失败和已取消任务。
   - 当前任务进度、预计消耗、错误原因、重试和定位节点。

### 4.2 顶部菜单功能矩阵

| 分组 | 控件 | 完成标准 |
| --- | --- | --- |
| 页面导航 | 首页、灵感生图 | 点击后分别进入案例首页与单图工作台；不得被画布拖拽手势截获 |
| 项目管理 | 项目切换、名称、新建、复制、归档/恢复、删除 | 每个控件执行对应持久化动作；危险操作必须二次确认 |
| 状态与交付 | 保存状态、积分、最终稿下载 | 状态实时更新；积分只读；存在最终稿时可直接下载原图 |
| 历史操作 | 撤销、重做 | 可用状态正确，执行后节点、采用状态和选择状态同步恢复 |
| 视图操作 | 缩小、比例、放大、适应内容、聚焦选中 | 点击不清空当前选择；视口按对应规则更新 |
| 查找与导航 | 搜索、缩略地图 | 面板可开关、结果可定位；导航框可开关和移动 |
| 画布整理 | 自动整理、清空 | 自动整理可撤销；清空必须确认并可撤销 |

画布手势仅允许从非控件的画布空白区域开始。画布平移、框选和节点拖动期间必须禁止浏览器原生文字选择与图片拖拽；输入框和文本域仍允许正常选择文字。

空间层级从低到高固定为：画布内容、普通悬浮面板、缩略地图、模态窗口、精灵。缩略地图允许停靠在画布任意位置；精灵在所有业务页面保持可见、可移动，并拥有最高空间优先级。

### 4.3 核心对象

- 画布项目：一次连续创作的持久化容器。
- 节点：画布上的最小内容单元。
- 素材：用户上传、历史生成或系统导入的可复用图片。
- 生成任务：一次可恢复、可取消、可结算的服务端工作。
- 图片版本：一次成功生成或编辑得到的不可变结果。
- 分支关系：版本之间的来源和演进关系。
- 当前采用版本：用户明确选中的最终候选，不因新生成自动覆盖。
- 编辑标注：蒙版、涂抹、保留区或扩图范围等结构化数据。

## 5. 核心用户流程

### 5.1 新建项目并首次生成

1. 用户进入无限画布。
2. 系统打开最近项目；没有项目时显示新建引导。
3. 用户输入项目名称，可跳过并使用自动名称。
4. 用户输入想法，或上传/选择一张图片。
5. 用户选择模型、尺寸、质量和生成数量。
6. 系统显示本次预计积分并做参数校验。
7. 用户确认生成，系统创建持久化任务节点。
8. 任务完成后，结果节点自动出现在来源节点右侧。
9. 系统保留来源、参数、价格和任务记录。

### 5.2 从结果继续分支

1. 用户选中任意图片节点。
2. 输入修改要求，并指定图片用途：主体、风格、构图或普通参考。
3. 系统以选中图片为父版本创建任务。
4. 新结果连接到父节点，但不改变当前采用版本。
5. 用户可继续分叉、比较或采用。

### 5.3 局部编辑

1. 用户打开图片节点的大图编辑视图。
2. 使用画笔标记需要修改的区域，支持擦除、调整笔刷和清空蒙版。
3. 输入局部修改说明。
4. 系统预览蒙版覆盖范围，并展示价格。
5. 提交后创建新的子版本，原图保持不变。
6. 成功结果返回画布，并保存蒙版和参数以便重做。

### 5.4 版本比较与采用

1. 用户选择 2 至 4 个图片节点。
2. 进入并排或滑杆比较。
3. 可查看提示词、模型、尺寸、时间和积分差异。
4. 用户将其中一个版本设为“当前采用”。
5. 采用状态在画布、项目列表和导出页面保持一致。

### 5.5 恢复未完成工作

1. 用户刷新页面或重新登录。
2. 系统从服务端读取项目快照和增量变更。
3. 排队或运行任务重新挂接到原任务节点。
4. 已完成结果自动补到对应父节点下。
5. 页面定位到用户上次视口；若视口无效则定位当前采用版本。

### 5.6 多参考图辅助改图

1. 当前选中的图片是“主编辑图”，决定版本关系和主要保留对象。
2. 用户可把画布上的其他图片加入“辅助参考托盘”，并标记主体、风格、构图、色彩或普通参考。
3. 辅助参考图保持独立画布节点，不因加入托盘而改变父子关系，也不复制已有云端文件。
4. 参考图按托盘顺序发送；主编辑图始终排第一，辅助图随后，数量和格式必须服从当前模型能力。
5. 用户可从本地拖入图片、选择本地文件夹中的多张图片，或从资源库选图；导入后立即形成可追溯节点，并可加入参考托盘。
6. 模型不支持参考图、数量超限或格式不兼容时，在创建任务和扣费前阻止提交，并明确指出需要移除的参考图。
7. 在非输入区域粘贴剪贴板图片时，图片上传到素材库并进入当前主图的辅助参考；没有主图时，第一张粘贴图片成为主图。
8. 画布上的图片实体可直接拖入参考托盘；引用属于主图的一跳静态关系，同一实体可被多个主图分别引用。
9. 每条引用以蓝色虚线连接“参考实体 → 主图”。引用关系不递归、不传播变化，也不把参考实体自己的参考图继续展开，避免形成无限引用链。
10. 当前主图使用明显的高亮描边、光晕和“主图”标识，必须与普通选中、最终稿和辅助参考状态清楚区分。

### 5.7 失败重试与再做一份

1. “重试任务”只用于失败、取消或中断的任务，必须复用原任务节点 ID、坐标和父版本。
2. 重试后原任务节点直接恢复为排队状态，成功结果在该节点原位替换，不新增第二张任务卡。
3. “再做一份”用于对成功图片生成另一个方案，必须创建新节点，旧结果保持不变。
4. “再做一份”的新任务节点固定出现在当前可见画幅右侧中央，用户无需平移或缩放即可看到。
5. 两种动作均复用原提示词、服务、尺寸、质量和参考图，但语义、位置与版本关系必须严格区分。

## 6. 功能需求与验收标准

状态定义：

- 已有：当前本地版本已具备基本能力。
- 部分：存在界面或局部逻辑，但尚未达到正式验收标准。
- 未做：当前未实现。

## 7. 关键交互规则

### 7.1 选中规则

- 单击节点：只选中该节点，并在右侧显示其属性。
- Shift 单击：加入或移出多选集合。
- 空白处拖框：选择相交或完全包含的节点，产品设置中固定一种规则。
- 单击空白处：清除选择，但不清除提示词草稿。
- 双击图片：打开大图预览。
- 双击想法节点：直接编辑提示词。

### 7.2 拖动画布规则

- 空白区域左键拖动或按住 Space 拖动：平移画布。
- 节点标题区域拖动：移动节点。
- 图片内容区域默认不触发浏览器原生拖图。
- 拖动到视口边缘时可以缓慢自动滚动画布。
- 拖动结束后写入一次位置变更，不在每一帧请求服务端。

### 7.3 删除规则

- 删除画布节点只删除该项目中的引用。
- 删除父节点时，子节点保留原来源快照，并显示“来源已从画布移除”。
- 删除当前采用或锁定节点需要二次确认。
- 清空画布不删除素材库、生成历史和积分记录。
- 正常项目删除采用软删除并进入“我的画布”底部的独立回收站。
- 回收站项目可恢复，也可在二次确认后彻底删除；彻底删除只清除画布项目、节点和关系，不删除素材库、生成历史或账单记录。

### 7.4 自动保存规则

- 文本停止输入 800 毫秒后保存。
- 节点停止移动后保存。
- 结构操作立即保存。
- 顶部显示“保存中”“已保存”“保存失败”。
- 保存失败不得伪装成成功；本地保留待同步变更并允许重试。

### 7.5 任务与结果落位规则

- 提交生成时，以来源节点右侧空位创建任务节点。
- 完成后任务节点原位转换为结果组，不突然跳到别处。
- 一次生成多张图时，同组纵向排列或折叠成结果组。
- 失败任务保留在画布，显示原因、退款状态和重试按钮。
- 取消任务保留记录，可删除任务卡，但不能抹掉账单记录。
- 失败任务重试必须复用同一个画布节点 ID 和坐标，旧终态任务记录在新任务创建成功后释放，不允许出现重复任务卡。
- “再做一份”创建新节点，并以当前视口安全区的右侧中央为落点；无论原节点在何处，新节点首次出现都必须在当前画幅内可见。

### 7.6 参考图规则

- 选中图片是主编辑图；辅助参考图由参考托盘管理，不因普通多选而隐式加入。
- 拖入或从文件夹导入时，如果已有主编辑图，则保持主图选中，新图自动进入辅助参考托盘；没有主图时第一张成为主图，其余进入托盘。
- 从资源库加入时复用 `asset_id`，禁止重新上传或复制原文件。
- 节点的参考用途和顺序随项目保存；移出画布时同步移出参考托盘。
- 参考图超过模型上限时不静默截断，应阻止生成并提示当前数量和允许数量。

## 8. 生成任务状态机

```text
draft
  -> validating
  -> queued
  -> running
  -> completed
  -> failed
  -> cancelling -> cancelled
  -> interrupted
```

状态要求：

- `draft`：仅客户端草稿，不计费。
- `validating`：服务端校验参数和余额，不允许重复提交。
- `queued`：任务已持久化并完成积分预留。
- `running`：工作进程已领取任务。
- `completed`：至少一个结果已持久化，积分完成结算。
- `failed`：无有效结果，积分已释放或退款。
- `cancelling`：已请求取消，等待供应商或工作进程确认。
- `cancelled`：没有继续生成，积分按实际执行规则处理并可追溯。
- `interrupted`：服务重启等原因导致运行中断，允许安全重试且不重复扣费。

任何终态都必须包含：任务 ID、创建时间、最终时间、父节点 ID、参数快照、报价、实际积分、结算引用和可理解的状态说明。

## 9. 积分与计费规则

1. 客户端报价仅供显示，最终价格由服务端根据同一模型配置重新计算。
2. 提交任务使用唯一幂等键，重复请求返回同一任务，不再次预留积分。
3. 任务进入队列前完成参数、权限、余额和素材可访问性检查。
4. 批量返回多张图片时，报价必须明确是单张价格还是总价。
5. 成功结算、失败释放和取消处理都必须幂等。
6. 部分成功时按实际成功结果和既定供应商成本规则结算，并明确显示。
7. 重试是新任务，必须引用原任务，但使用新的结算引用。
8. 超时只代表前端暂时未得到结果，不能直接判定失败或再次提交。
9. 管理员免扣或特殊账户也要保留价格与任务记录，便于审计。
10. 用户可从任务卡进入对应积分明细，但不能看到供应商密钥或内部敏感成本。

## 10. 错误信息规范

错误不能统一显示“生成失败”。界面至少区分：

| 错误类别 | 用户提示方向 | 可执行操作 |
| --- | --- | --- |
| 未登录 | 登录后继续，草稿已保留 | 登录 |
| 余额不足 | 显示预计积分和当前余额 | 去充值 |
| 模型不可用 | 当前服务暂不可用 | 切换模型、稍后重试 |
| 尺寸不支持 | 明确列出可用尺寸 | 自动改为推荐尺寸 |
| 参考图不支持 | 说明数量、格式或模型限制 | 移除图片、切换模型 |
| 图片过大或格式错误 | 显示限制 | 重新上传 |
| 内容审核未通过 | 给出安全、克制的修改建议 | 修改提示词 |
| 网络中断 | 任务可能仍在运行 | 重新连接、查看任务 |
| 任务队列已满 | 说明最大任务数 | 删除终态任务 |
| 生成超时 | 不自动重复扣费 | 继续等待、查看任务 |
| 存储失败 | 结果暂不可交付 | 自动重试保存、联系客服 |
| 权限不足 | 不泄露对象是否属于他人 | 返回项目列表 |

## 17. 发布门禁

每次准备发布无限画布时，必须同时满足：

1. 对应阶段所有功能编号已完成或有明确延期记录。
2. 对应阶段所有必测清单已有证据。
3. 全量自动化测试和生产构建通过。
4. 浏览器无阻断错误、无横向页面溢出、无明显交互死角。
5. 真实任务验证积分、结果保存和下载成功。
6. 准备数据库与文件存储备份。
7. 准备可执行的回滚版本或镜像。
8. 发布后检查登录、项目、生成、任务恢复、积分和下载路径。
9. 未经用户明确授权，不切换生产环境。

## 18. 需求变更记录规则

- 新功能必须分配新的 `IC-*` 编号，不复用已删除编号。
- 修改验收口径时，在文档顶部提升版本号并更新日期。
- 功能完成后，将状态改为“已完成”，并附代码、测试或浏览器验收证据。
- 延期功能标记目标阶段和原因，不能静默删除。
- 缺陷使用关联功能编号记录，避免只按页面截图追踪。
- 自动化测试名称应包含对应验收编号，例如 `IC-AT-010 duplicate submit is idempotent`。

## 19. 最终完成定义

只有当用户能够完成下面整条路径，才能称为“无限画布完整功能”：

> 新建项目 → 导入或生成原图 → 创建多个分支 → 局部修改 → 比较版本 → 选定最终稿 → 下载交付 → 关闭页面 → 换设备重新打开并继续创作。

这条路径中的素材、提示词、节点位置、任务状态、积分记录、分支关系和最终采用版本必须全部可恢复、可解释、可测试。
