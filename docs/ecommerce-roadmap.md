# 电商视觉工作台 P0-P3 实施路线

更新日期：2026-08-06

## P0：商品项目与可运行闭环

目标：让小白用户不写 Prompt，也能从商品资料开始生成并保存平台图片。

1. 商品项目：平台、行业、商品事实、目标用户、卖点、规格、禁用内容、视觉方向。
2. 平台套图槽位：淘宝 / 天猫、抖音电商、Amazon、Shopify。
3. 商品素材上传：商品原图、Logo、包装、参考图及素材权属确认。
4. 商品母版：先确认产品结构、颜色、包装文字和配件数量，再开始扩图。
5. 单槽位生成：每张图片独立生成、扣费、保存、失败退款和内容审核处理。
6. 项目历史：按项目、平台、槽位和版本查看结果。

当前进度（2026-08-06）：

- 已完成商品项目、四平台槽位和 SQLite 持久化。
- 已完成商品原图、包装、Logo、参考图上传，并兼容本地磁盘、Azurite 和 Azure Blob。
- 已完成商品母版选择；首张商品原图会自动成为母版，也可手动更换。
- 已完成单槽位生成、1积分预留、失败退款、项目/槽位/版本记录、云端保存和下载。
- 已使用模拟模型响应验证完整链路；真实 UniKeyX 生成需在项目运行环境配置 `AI_API_KEY` 后由用户主动点击测试，避免未经确认产生费用。
- 下一步是完善版本列表和进入 P1 的商品一致性评测，不自动开启批量生成。

## P1：稳定的一致性套图

目标：让同一商品在多张图片、多种比例和多个平台中保持一致。

1. 商品主体锁定和母版引用。
2. 多参考图上传、排序和用途标注。
3. 按槽位自动构建 Prompt，用户只调整结构化选项。
4. 单张重做、局部修改、版本回退和结果锁定。
5. 淘宝 / 天猫、抖音、Amazon、Shopify 的首批行业模板。
6. 批量任务队列、进度和单张失败恢复。

## P2：专业制图与平台交付

目标：从“AI 生图”升级为可交付的电商视觉生产工具。

1. 可编辑文字、价格、Logo、参数和活动标签图层。
2. 平台规则检查：比例、像素、白底、文字安全区、文件格式和槽位完整性。
3. 详情页模块编排、短视频封面与分镜。
4. 尺寸图、包装清单、对比图、SKU 变体等专业制图组件。
5. 按平台规则命名并导出 ZIP。
6. 项目复制、模板保存和跨平台改版。

## P3：商业化生产平台

目标：具备稳定收费、云端部署和规模化运营能力。

1. Azure PostgreSQL、Azure Blob Storage 和任务队列迁移。
2. 项目级积分预估、批量扣费、失败退款和账单明细。
3. 套图套餐、行业模板包、试用额度和付费转化路径。
4. 管理后台：用户、积分、订单、生成成本、审核失败率和模板使用率。
5. 团队空间、品牌资产库、成员权限和审批。
6. 规则版本、素材授权记录、操作审计、备份与恢复。
7. 生产监控、限流、并发队列、告警和灾难恢复。

## 执行原则

- 每次只交付一个可验证闭环，不同时铺开多个半成品模块。
- 先使用 SQLite 和本地 / Azurite 存储完成业务验证，再迁移 Azure。
- 原始商品事实与生成 Prompt 分离，避免用户必须理解提示词工程。
- 每张图片拥有独立状态和版本，单张失败不要求整套重做。
- 真实平台案例只用于研究信息结构，不复制第三方图片、Logo、包装或文案。
