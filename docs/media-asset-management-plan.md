# Pic365 资产管理补全规划

日期：2026-09-22。基于当前本地代码检查，不代表生产环境已验证。已在本地实现左侧菜单主题修正，以及关键词、标签、时间检索和排序；其余能力仍为规划。

## 当前基础

- 图片、视频、音频统一上传及预览，生成结果自动入库。
- 按类型、来源、收藏、项目素材、团队和分类浏览。
- 名称、分类、标签统一关键词搜索；资产名称、标签编辑；一个资产归入多个分类。
- 标签精确筛选、按入库年/月/日/区间检索，支持交叉条件；最新、最早、名称、文件大小排序。
- 多选批量归类、批量移入回收站；单项下载和恢复。
- 团队、成员、个人共享、查看与编辑权限及撤销。
- 原始文件复用、项目关联、项目引用阻止永久删除、存储用量统计。

证据入口：`src/media-asset-center.jsx`、`api/assets.js`、`api/assets/projects.js`、`api/_lib/media-assets.js`、`tests/media-assets.test.js`。

## 第一阶段：安全、找得到、拿得走

| 优先级 | 能力 | 当前缺口 | 建议与验收 |
| --- | --- | --- | --- |
| P0 | 删除安全 | 详情中的永久删除和清空回收站直接执行，没有独立确认 | 展示数量、不可恢复提示、占用空间；二次确认后执行；返回成功、失败、仍被引用的项目清单；不新增自动清理策略 |
| P1 | 搜索与排序 | 已实现关键词、标签、时间筛选、排序与逐项清除；尺寸筛选和跨会话记忆待评估 | 保留类型、来源及团队浏览；先验证真实使用，再扩展高级条件，避免工具栏过载 |
| P1 | 批量交付 | 多选工具条主要是归类和删除，没有资产库批量下载 | 多选打包下载，保留原图；同名文件去冲突；显示进度和失败明细；大包服务端处理；逐项验证访问权限 |
| P1 | 分类维护 | 能创建、删除、多选归类，缺少改名、改色及排序入口 | 增加分类编辑与排序；保留多分类语义；批量操作明确区分“添加分类”和“移除分类”，不隐式覆盖 |
| P1 | 引用位置 | 已有项目关联查询，详情没有完整使用位置入口 | 详情显示关联项目和用途，允许跳转；取消项目引用不删除原图；跨团队只显示当前用户有权查看的项目 |

建议先交付 P0，再交付搜索排序和批量下载，避免同时扩展所有工具。

## 第三阶段：空间与智能整理

- 重复文件提示：上传时已有 SHA-256，可先做同账户完全相同文件识别，再评估相似图。先提示复用，不自动合并或删除。
- 空间管理：按大小列出大文件、回收站、长期未使用文件；共享与项目引用关系核验后再清理。
- 品牌素材包：按品牌、商品、活动组织 Logo、母版、参考图与最终稿；先复用分类和项目关联，不复制一套文件存储。
- 可选智能标签、以图找图：放在普通检索完善之后；先明确成本、隐私范围和是否用户主动开启。

## 检索规则（本地已实现）

- 关键词按完整输入作包含匹配，名称、当前用户分类名、资产标签三者任一匹配即可。百分号、下划线按普通文字处理，不作为数据库通配符。
- 左侧浏览范围、关键词、标签、来源、入库时间之间取交集。切换左侧分类保留关键词、标签和时间；来源导航不再悄悄保留旧来源。
- 标签并非新增一套数据，复用 `asset_tags` 与资产 ID 的真实关联。详情标签支持中英文逗号、分号、换行，忽略大小写去重，最多 20 个、每个最多 40 字符，保存后立即参与搜索。
- 卡片显示标签和入库日期；标签可点击筛选，更多标签在详情查看。只有查看权限的共享资产不能编辑标签；原有权限规则不改变。
- 入库时间采用 `assets.created_at`，不是照片 EXIF 拍摄时间或最后修改时间。界面按北京时间，服务端转换成 UTC 起止边界；结束日期包含当天全部时间。
- 年、月、日切换尽量继承已选时间；改动具体时间后点勾或回车应用。区间不完整、日期无效、起止倒置不应用，也不会自动扩大到全部资产。
- 标签选项来自当前范围、关键词及时间匹配的全部有权访问资产，不只取已加载的第一页；为便于切换标签，选项统计不受当前选中标签自身限制。
- 结果显示真实匹配总数与已加载数。切换检索条件重置分页和多选；连续请求取消旧请求，旧响应不能覆盖新结果。
- 条件可逐项取消；“清除检索条件”保留左侧分类/团队浏览范围，不清空资产，也不修改标签。
- 检索控件与上传、管理按钮分区，维持浅色、深色、纯黑一致的结构。

验证：新增日期/标签规则及真实接口测试，通过 376 项全量测试；隔离测试数据库下检查了标签保存→关键词检索、分页→新条件、年/月/日/区间、三主题与手机宽度。没有修改真实资产数据或发布服务器。
