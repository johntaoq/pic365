# P2 专业交付使用与实现说明

更新日期：2026-08-07

## 用户路径

1. 在“套图生成”中选择每个槽位的采用版本。
2. 打开“6. 专业交付”，系统按平台和槽位准备交付文档。
3. 在“单图精修”中修改结构化信息；默认推荐方案可以直接使用。
4. 点击“检查本图”或在“详情页编排”中点击“检查全部”。
5. 调整顺序和是否加入交付包，然后导出 ZIP；可同时生成一张详情长图。
6. 成熟项目可以复制、跨平台改版，或保存为个人模板。

## 三层易用性设计

- 默认层：系统按平台、槽位和制图类型自动选择推荐主题、版式、文字显示和输出尺寸。
- 编辑层：只展示业务字段，例如标题、卖点、尺寸、清单和变体，用户不需要操作自由画布。
- 高级层：折叠主题、信息区、格式、适配方式和安全区预览，避免新用户被复杂选项干扰。

## 平台检查与导出

- 检查结果分为必须修正和建议优化；存在必须修正项时，整套 ZIP 不允许导出。
- Amazon 合规主图额外检查文字、Logo、价格、标签叠加和白底边角。
- 尺寸图、包装清单、对比图、SKU 变体和步骤图会检查对应结构化数据是否完整。
- 纯编排操作（排序、是否加入交付包、安全区预览）不改变实际图像，因此保留已有检查结果。
- 改动图像内容、版式、格式、尺寸或渲染参数后，必须重新检查。
- 导出支持 PNG、JPEG、WebP；整套 ZIP 包含图片、清单 JSON，以及可选详情长图。

## 数据与复用边界

- 每个项目槽位对应一份持久化交付文档，保存内容、版式、顺序和检查结果。
- 同平台复制会复制商品事实、身份规范、素材和交付版式，但不会复制旧生成结果。
- 素材复制为新的存储对象，删除或修改副本不会影响原项目。
- 跨平台改版保留商品事实和素材，槽位与视觉方向切换为目标平台推荐方案。
- 个人模板只保存流程、槽位、视觉和交付设置，不保存商品图片、商品名称或专属文案。

## 本地与 Azure 迁移

- 当前业务数据使用 SQLite，本地对象存储可使用 Azurite。
- P3 迁移到 Azure PostgreSQL 和 Azure Blob 时，应保持文档 ID、项目/槽位唯一关系、素材物理复制语义和导出命名规则不变。
- 渲染与 ZIP 打包属于 CPU 密集操作，生产环境应迁移到独立任务队列，并保留接口限流和任务可取消能力。
